# Blind oracle set: sound-level engine (signals, nights, dose)

Written without reading the engine (`src/`, `oracle/`, `modules/`). Inputs were only `docs/SPEC.md` (sec. 7, 15, 16), `docs/FORMATS.md`, `docs/QA_SIGNALS.md`, plus primary sources: IEC 61672-1 Annex E weighting constants and Table 3/4 values (via SPEC 7.2/E4, cross-checked against the published nominal table), NIOSH 98-126 (sec. 1.1.3 TWA, sec. 1.3.3 "80 to 140 dBA" integrated), OSHA 29 CFR 1910.95 + App. A (dose/TWA formulas, slow response, 80-130 dB integrated), EU Directive 2003/10/EC Art. 2/3 (LEX,8h per ISO 1999; 80/85/87 dB(A), 135/137/140 dB(C)).

- Counts: **46 PCM fixtures** (27 at 48 kHz, 19 at 44.1 kHz, 2400 assertions), **20 nights** (3 with nothing to detect, 3 interpretation-dependent), **13 dose cases**.
- Formats, tolerances, assertion fields: `FORMAT.md`. Recompute everything from the files: `python3 -I check.py` (stdlib only, about 30 s). Last run: 0 mismatches.
- The generator scripts are kept outside this folder, in the sibling folder `sm-gen-c04b009714d0/` (`gen_signals.py`, `gen_nights.py`, `gen_dose.py`, `gen_docs.py`, and the diagnostic `diag_iir.py`).
- **sourced** = the expected value follows from a cited definition or standard. **UNCONFIRMED** = it rests on an assumption named on that line. Inside a sourced fixture, single assertions can still be UNCONFIRMED (field `status`).
- Discriminating fixtures: an engine with a plain, uncorrected bilinear A/C filter fails S15, S17, S19, S20, S23 and S24 (55 assertions), exactly where SPEC A1 asks for the high-frequency correction stage. Pink at 48 kHz misses by -0.21 dB, matching SPEC 7.2.

## Assumptions (UNCONFIRMED) and SPEC gaps this set exposes
- Time weighting starts from y[-1] = 0 (SPEC 7.3 gives no initial state). Only early Slow values and second-0 minima depend on it, and they are flagged `initial_state_assumption`.
- A trailing part-second (S45) produces a record, with the energy mean over the samples present.
- Above 12.5 kHz SPEC A1 sets no limit. The broadband interval tolerances assume |error| <= 7 dB there; 16 kHz tones are `info_only`.
- The 0.1-dB A1 multitone tolerance is also applied to dense pink noise (S19/S20).
- Burst-second LAeq allows 0.05 dB for filter onset transients (bursts S25-S29).
- GAP 1, detector (N07, N08, N20): SPEC 7.7 excludes event seconds from B and needs >= 60 usable seconds, but does not say what happens once a long event fills the 600-s window. Literal reading: B is undefined, so every event longer than about 540 s is cut, and a slow party becomes a saw-tooth of 540-s events. "Hold the last B" reading: one event per disturbance. The owner or builder should decide; A5 is only fully testable after that.
- GAP 2, detector (N20): do quiet seconds inside a merged event count as "inside an event" for B? This only matters together with GAP 1.
- GAP 3, detector (N20): does the 600-s window include the current second? This matters only at the warm-up edge and with GAP 1.
- GAP 4, overload (S40): the flat-top rule ">= 4 consecutive equal samples with |x| >= 0.5" flags an UNCLIPPED low-frequency sine after PCM16 quantisation (equal samples at every peak). That is the literal expectation. It is likely a false positive on Android PCM16 input; consider requiring |x| near the input maximum or a longer run.
- Mic-busy CSV rows: FORMATS.md says both "mic-busy seconds have empty levels" and "gaps have no row". N13 uses rows with empty cells for mic-busy, and no rows for other gaps.
- "Events between 22:00 and 06:00" (SPEC 7.8) is counted by local start time.
- Dose with gaps (D10): projected dose and LEX,8h use Te = valid seconds. The wall-clock alternative is given in `alternative_if_other_reading`.
- NIOSH 80-dBA threshold: SPEC 7.6 calls it an assumption. NIOSH 98-126 sec. 1.3.3 states it ("80 to 140 dBA ... shall be integrated"), so it is treated as sourced here.
